It fixes the load-bearing decisions and sketches data-model/contract shapes as **guidance** for the epic's features (F-CB-0…F-CB-5, filed from [#289](https://github.com/k-sandhu/lumen-copilot/issues/289)).

## Context

[ADR-0009](0009-connector-framework-and-web-source.md) shipped the connector *framework* — the `Connector` protocol (`validate_config` / `sync` / `health`), the auto-discovered registry, the tenant/owner-scoped `sources` table, the Celery sync task, and one connector (`web`, unauthenticated, public content, owner-only visibility) — and **deliberately deferred** everything a real enterprise connector needs: authenticating to a source, mirroring per-item ACLs, and syncing incrementally. The sponsor has now committed epic [#289](https://github.com/k-sandhu/lumen-copilot/issues/289) (Connector Breadth v1) and chosen **Google Drive** as the first managed connector.

What already exists and is reused, not re-derived:

- **Egress discipline in one place:** `backend/app/net/egress.py` (the shared SSRF primitive: blocked-range checks, resolve-all/reject-any, IP-pinning), with consumers including `connectors/web/fetch.py`, the MCP guarded httpx client (`backend/app/mcp/egress.py`, ADR-0012 §4), and the LLM provider catalog (`backend/app/llm/provider_catalog.py`).
- **Credentials in one place:** the CC-C secrets vault ([#209](https://github.com/k-sandhu/lumen-copilot/issues/209)) — envelope-encrypted, write-only, plaintext obtainable only in-process via `secrets_service.get_secret_plaintext(...)`; `mcp_servers.auth_secret_ref` (ADR-0012 §5) is the recorded pattern for "a row references a credential, never holds one".
- **Permission enforcement in two lockstepped chokepoints** (ADR-0010 §4): the Postgres predicate (`retrieval/queries.py::_document_permitted` — `tenant AND (owner ∈ owners OR grant EXISTS)`) and the engine filter (`search/filters.py::SearchAllowFilter` — mandatory `tenant_id` term + owner/granted-doc/granted-collection terms), with Postgres hydration re-checks as defense in depth. The comment in `retrieval/permissions.py` already names "mirrored connector ACLs" as the deferred widening of this exact seam.
- **The decided ACL model** ([spec 0004](../specs/0004-security-and-domain-invariants.md) §2.2, *not re-litigated here*): connector documents store a **mirrored ACL principal-set** normalized to tenant principal IDs, refreshed on sync; retrieval intersects the requester's principals with the document's set; **stale or unknown ACL ⇒ deny** (configurable freshness window); the system never grants access the source would deny.

There is **no OAuth machinery anywhere in the app today** (grep-verified) — the authorization-code flow, state handling, and token storage designed here are greenfield, built once at the framework level so the second managed connector reuses them.

## Decision

### 1. Source authentication — OAuth 2.0 authorization-code + PKCE, initiated by a tenant admin; tokens live in CC-C

- **Flow.** Authorization-code with **PKCE (S256)** and offline access (refresh token). A connector that needs OAuth declares it via the SDK (§4); the **framework** owns the generic machinery (`connectors/oauth.py`: authorize-URL construction, state, PKCE, code exchange, token refresh) — nothing Google-specific leaks out of `connectors/gdrive/`.
- **Who may connect — and create: tenant admins only** (`Role.ADMIN`, enforced via the existing `require_roles` dependency — INV-5). Both `POST /sources` with a managed `type` (creating the `pending_auth` row) **and** `POST /sources/{id}/connect` are admin-gated; connecting a managed source imports organization content *and* its ACLs — an admin trust decision, unlike the owner-scoped `web` source. **Every managed-source mutation is admin-gated at action time** — create, connect, **reconnect, on-demand sync, and disconnect/delete** — checked per-request against the caller's *current* roles, never a role held at creation: a source owner demoted from admin loses all of them (mandatory negative tests: non-admin create/connect → 403; demoted owner reconnect / sync-now / delete → 403). The owner-scoped semantics of `web` sources are unchanged. Tier classification: retrieval over connector content is **T0**; the management mutations above are **T1 source-management writes** (admin-gated, audited — the ADR-0009 §5 classification), with the provider consent screen serving as the explicit human authorization of the connect action.
- **Endpoints (contract frozen in F-CB-0, shape fixed here):**
  - `POST /sources/{id}/connect` *(admin)* → `{authorization_url}` for a source row in the new `pending_auth` status.
  - `GET /sources/oauth/callback?state&code` — the **one** redirect-target endpoint, shared by all OAuth connectors. It is unauthenticated in the JWT sense (a browser redirect carries no bearer header) and instead authenticated by **`state` as an opaque, high-entropy, single-use handle** — a random 256-bit value that is a *key into a server-side Redis record*, never a carrier of data: `{tenant_id, user_id, source_id, code_verifier, provider, redirect_uri, flow_generation}` all stay server-side (a signed-token design was rejected — signing gives integrity, not confidentiality, and the PKCE `code_verifier` must never transit the browser). The record has TTL ≤ 10 min and is **consumed atomically before the code exchange** (a second/concurrent callback with the same state finds nothing and is rejected). Each source carries a **monotonic connect generation**: starting a new flow atomically increments it and stamps the new record with the new value, and callback validation **requires the record's generation to equal the source's current one** — starting flow N+1 therefore invalidates flow N even inside its TTL (negative test: the superseded flow's callback is rejected). At callback time the server **re-authorizes from current state, trusting nothing carried by the flow**: the acting user still holds `Role.ADMIN` in that tenant (a demoted admin's callback is denied), the source row still exists and is in a connectable status, and the provider/redirect-URI match the stored record. Missing/expired/replayed/forged state, a failed re-authorization, or a provider error response → **fail closed: no code exchange, no secret written** (INV-4/INV-5/INV-8 negative tests). On success the server exchanges the code, stores tokens (below), marks the source `pending`, enqueues the first sync, and 302-redirects to the Sources screen.
- **Token storage.** The **refresh token** is stored via `SecretsService.store_secret` under a new `SecretKind.CONNECTOR_OAUTH` (`connector_oauth`), owned by the connecting admin; the `sources` row gains **`auth_secret_ref`** (nullable UUID → the CC-C secret), the exact `mcp_servers.auth_secret_ref` pattern. The migration **widens the `ck_secrets_kind` CHECK** alongside the Python enum — the DB constraint currently admits only `mcp_auth|search_api|other`, so the enum alone would fail at the database boundary. **Access tokens are never persisted** — the sync task obtains one per run via the refresh grant and holds it in memory only. Token material never enters `sources.config`, logs, audit metadata, or any API response.
- **Token use & refresh.** The Celery sync task reads the refresh token via `get_secret_plaintext(auth_secret_ref, accessor=AuditActor.system())` (the exact MCP/LLM-provider adapter pattern, so `secret.accessed` names the reader). A rotated refresh token is re-stored in place (the vault upsert keeps the handle stable). A dead grant (`invalid_grant` — revoked/expired) fails the sync closed: source `status=error`, health reports **reauthorize required**; re-connect runs the flow again onto the same row.
- **OAuth client credentials** (the platform's Google app registration: client id/secret) are **deployment-level config** via `core/config.py` (`GDRIVE_OAUTH_CLIENT_ID` / `GDRIVE_OAUTH_CLIENT_SECRET`, blank-refused outside `local` per the config conventions). Per-tenant bring-your-own-client is a recorded follow-up, not v1.
- **Deleting a source** (or the connector being disconnected) deletes the referenced secret via the vault (audited `secret.deleted`) in the same operation that removes the row and its documents — no orphaned credentials (the #139/#269 reconcile lesson applied to secrets).
- **Audit (additive, INV-6):** new `source.connected` action (records the source, the acting admin, the connected account email + granted scopes — never tokens, codes, or verifiers), joining the existing `source.added/synced/deleted`; **spec 0004 §2.4's additive list is updated in this same change**, and `domain/audit.py` + the exact-set pin in `tests/test_audit_taxonomy.py` update in lockstep in F-CB-1. **Failure outcomes are audited at both stages.** *Initiation* (the JWT-authenticated `connect`/create/reconnect endpoints — state does not exist yet, but the actor and tenant are token-bound): a denied or errored initiation emits **`permission.denied`** (the existing deny action, resource_type `source`) from the JWT-bound actor — negative test included. *Callback*: when the state record resolves to a trusted tenant but the flow then fails — re-authorization denied (demoted admin, dead source), superseded generation, provider error, failed exchange, failed refresh — emit `source.connected` with `outcome=denied|error` (the taxonomy's existing outcome field; no new action). A callback whose state does **not** resolve provides no trusted tenant to attribute — it is recorded in ops telemetry (rate-limited, structlog) rather than fabricating a tenant-scoped audit row from attacker-controlled input; fail-closed attribution is deliberate.

### 2. ACL mirroring — the concrete contract (implements spec 0004 §2.2)

- **Domain shape.** A capability-declaring connector returns, per fetched document, a **mirrored principal-set** — the source's allow-list normalized to Lumen principals. Principal vocabulary (v1): `user:<lumen_user_uuid>` and `tenant` (tenant-wide). The mapping (`map_acl`, §4) is **pure and fail-closed**: anything it cannot map **grants nobody**.
- **Enforcement modes are exclusive — never-escalates made structural.** `documents` (and the index) gain an explicit **`acl_enforced` boolean** — explicit because an empty keyword array is indexed like a missing field and cannot discriminate "not a connector document" from "connector document nobody may see":
  - **`acl_enforced = false`** (uploads, `web` sources): today's predicate — `owner OR grant` — unchanged.
  - **`acl_enforced = true`** (managed-connector documents): access requires a **fresh mirrored-principal intersection, and nothing else** — the owner leg and the Lumen-grants leg **do not apply**. The connecting admin sees a document only when the mirror lists them (Drive's own owner/permission entries normally do); a Lumen grant can never admit a user the source denies; an **empty or stale mirror admits no one, including the owner**. Parity negative tests prove owner-denied and explicit-grantee-denied on empty/stale connector ACLs in **both** stores.
  - **The mode is never defaulted at write time.** The ingestion seam takes a **mandatory, no-default ACL-mode argument on every document write**; the sync task derives it structurally — any document originating from a `map_acl`-declaring connector is written `acl_enforced=true`, asserted by test (a managed-source document persisted with `acl_enforced=false` is a defect). The column's `default false` exists solely for the backfill migration of pre-existing upload/`web` rows, never as a code path. Spec 0004 §2.2's connector-documents bullet is updated in this same change to record the exclusive split (mirror-only; ownership/grants do not widen).
- **Identity mapping (v1: individually matched users, plus the one provably-safe wildcard).** Case-folded email matching within the connecting tenant only:
  - `type=user` → `user:<uuid>` iff the entry's email matches a tenant user's email; no match ⇒ drop. **Trust basis (v1, verified in code):** app-managed identity gives emails exactly one mutation path — tenant-admin creation/administration; no self-service email change exists — so a tenant email is an **admin attestation**, issued by the same authority that connected the source. The mapping consumes a **sync-time snapshot** of that attested directory (an email change propagates at the next ACL refresh, never mid-window). **Recorded hard gate:** self-service email mutation or SSO federation must not ship without switching ACL mapping to *verified* identities (the Google-subject ↔ Lumen-user link recorded below with domain binding) — until then, an unmatched or ambiguous email maps to nothing.
  - `type=anyone` (public/link-public) → `tenant`: every tenant member could read the item at the source regardless of their email domain, so the tenant-wide principal is a strict subset of the source audience — the subset proof holds even for guest members.
  - **`type=domain` ⇒ deny in v1.** The subset proof fails here: a Lumen tenant may contain guest users whose email domain is not the sharing domain, the current identity model carries only an unverified `email` (no verified-identity or workspace↔tenant domain binding), and the connected account's email is not an authoritative domain attestation — so a `tenant` mapping could expose a domain-restricted file to source-denied guests. Domain-restricted shares map to nothing until a **trusted Google↔Lumen domain/identity link** exists (recorded follow-up, filed with the group-expansion work). Negative test: a same-tenant guest outside the sharing domain retrieves nothing from a domain-shared file.
  - `type=group` ⇒ deny (unexpanded — Directory API / SCIM, CC-3 v2 territory, epic scope fence). Under-sharing is the deliberate failure direction.
- **Effective-read algorithm (Drive-specific; F-CB-2 implements exactly this, one fixture per case).** The mapper consumes each file's **own effective permission list** (requested fields: `type, role, emailAddress, domain, deleted, expirationTime, view, permissionDetails`, plus the file-level `inheritedPermissionsDisabled`) and admits an entry only when **all** hold: not `deleted`; **no `expirationTime` at all** — v1 does not model time-boxed shares, so an entry carrying *any* expiration (future or past) is denied and a mirror can never outlive a temporal grant (admitting them under an `acl_expires_at` bound is a recorded follow-up); `view` unset (a `view=metadata` entry never grants content access); `role ∈ {owner, organizer, fileOrganizer, writer, commenter, reader}` (the content-read set); and the `type` maps per the rules above. **Inheritance reduction:** when the file sets `inheritedPermissionsDisabled=true`, only entries whose `permissionDetails` mark them **direct** are considered — inherited entries still present in the list are ignored; otherwise the file's effective list (direct + inherited) is consumed as-is; a parent's list is never consulted directly. Fixture: a limited-access file inside a shared folder admits only its direct principals. **Any unknown type, role, or field state ⇒ deny that entry.** Each admit/deny case is a fixture in the never-escalate suite.
- **Fail-closed rules:**
  - a permissions fetch that errors ⇒ that document is **skipped this sync** and its `acl_synced_at` does **not** advance (never ingested/kept with unknown rights);
  - a document whose mapped set is **empty** is ingested but retrievable by **no one** via the ACL leg (it lights up when mapping improves), and sync health counts these (`unmapped_acl_count`) so an admin can see silent-deny volume;
  - a mirrored ACL older than the freshness window (`CONNECTOR_ACL_MAX_AGE_HOURS`, default 24) ⇒ **deny** — a stalled sync progressively hides connector content rather than serving stale rights.
- **Storage.** Postgres (source of truth): `documents` gains `acl_enforced` (bool, default false), `acl_principals` (jsonb array), and `acl_synced_at`. OpenSearch: the chunk doc + strict mapping gain `acl_enforced` (boolean), `acl_principals` (keyword array), and `acl_synced_at` (date) — touched in `IndexedChunk`, `_index_body`, the bulk writer, and `index_sync._to_indexed`; requires a mapping bump + the existing idempotent reindex path.
- **Enforcement — widen both chokepoints in lockstep, nowhere else:**
  - Postgres `_document_permitted` becomes **mode-split**: `(NOT acl_enforced AND (owner ∈ owners OR grant EXISTS)) OR (acl_enforced AND acl_principals ∩ requester-principals ≠ ∅ AND acl_synced_at ≥ now() − window)`;
  - `SearchAllowFilter.to_engine_filter()` mirrors the identical mode-split bool (the `acl_enforced=false` branch keeps today's owner/grant terms; the `true` branch requires the `acl_principals` terms match **and** the `acl_synced_at` freshness range) — the mandatory `tenant_id` term sits outside the split, untouched (INV-1);
  - hydration re-checks (ADR-0010 §4) re-evaluate the same widened predicate in Postgres before anything becomes a citation — the engine is never solely trusted.
- **Refresh cadence.** A document's `acl_synced_at` advances **only** when its ACL was fetched in that run, or a complete gap-free change-log replay attests it unchanged **with §3's container-cascade propagation applied** (a replay never attests a document a replayed folder/drive permission change cascades over) — never as a side effect of a sync that did not examine it. A source-side revocation is enforced at the next sync, and no later than the freshness window (the window is the recorded worst-case revocation-to-enforcement bound).

### 3. Change detection — cursor-based incremental sync (polling; webhooks stay out)

- **Framework interface — page-shaped, so the transaction boundary is expressible.** An optional capability: `fetch_changes(source, cursor, run)` yields an **iterator of `SyncPage`s**, each `{upserts: Iterable[FetchedDoc], deleted_external_ids: frozenset[str], next_cursor: str}`. The framework commits each page's document mutations **and** persists `sources.sync_cursor = page.next_cursor` **in the same transaction**; the terminal page's `next_cursor` is the provider's new baseline (Drive: `newStartPageToken`). `sync_cursor` is therefore always the exact resume point — a mid-replay page token after a crash, the completed baseline after a drained replay — one field, no ambiguity. Full `sync()` remains mandatory (bootstrap, and the fallback when a cursor is rejected); `sync_cursor` null = next sync is full. `FetchedDoc` widens **additively** (defaults keep the `web` connector untouched): `external_id`, `modified_at`, `acl` (the §2 principal-set).
- **Reconcile by identity, not wholesale.** With `external_id` present, the sync task upserts by `(source_id, external_id)` and deletes by `deleted_external_ids` — replacing the current delete-all-then-reingest reconcile for incremental runs (full runs keep it). `documents` gains `external_id` (nullable; unique per source when set).
- **Cursor bootstrap & commit discipline (fixed here — the correctness of incremental ACLs hangs on it):**
  - the start token is captured **before** the full enumeration begins, scoped to the right change log per mode — the user's own feed for My Drive / a My-Drive folder, the **Shared Drive's `driveId`-scoped log** for a Shared Drive *or any folder inside one* — so nothing that changes mid-enumeration is lost (the first incremental replay covers the enumeration window);
  - change pages are processed in order, and **document mutations + the advancing page token commit atomically per page batch** — a crash between pages resumes from the last committed token, never skipping a page and never re-serving half-applied state (tests: crash-between-pages resume, a corpus move mid-sync, partial permission-fetch failure within a page);
  - the stored cursor advances **per committed page** (the `SyncPage` transaction above); the terminal page carries the provider's new baseline, so a drained replay leaves `sync_cursor` at `newStartPageToken`;
  - **container-cascade propagation:** Drive does *not* emit one change per descendant when a folder's or Shared Drive's permissions change — a replayed change to a cascading container therefore **invalidates its descendants' ACLs**: the connector enumerates the affected subtree and refreshes those documents' ACLs in the same run, and where that enumeration fails or exceeds the run budget it leaves their `acl_synced_at` unadvanced so the freshness window degrades them to deny rather than serving pre-change rights; a replay "attests a document's ACL unchanged" (§2) only when no replayed container change cascades over it;
  - a failed per-document ACL fetch inside a page **does not advance that document's `acl_synced_at`** (§2) and schedules a bounded retry, escalating to a full resync if it keeps failing — an incremental run can therefore *narrow* freshness but never fake it;
  - an invalid/expired cursor (HTTP 410) clears `sync_cursor` and falls back to a full resync.
- **Cadence:** on-demand (`POST /sources/{id}/sync`, unchanged) plus a periodic poll per connected source via the existing Celery beat, interval `CONNECTOR_SYNC_INTERVAL_MINUTES` (default 60), always through the existing enqueue seam and its per-tenant rate limit. **Webhooks/push change notification is E7-2 and stays out** (epic scope fence).

### 4. Connector SDK — in-process capability protocols + a conformance kit

- **Trust model: in-process, first-party only.** v1 connectors are in-repo, code-reviewed Python under `backend/app/connectors/<name>/` — the same trust boundary as the rest of the backend, so **no ADR-0013 sandbox is required**. This holds **only** while every connector is first-party: third-party / push / SDK-only custom connectors (out of scope, epic fence) must revisit isolation *before* any foreign code loads — recorded here so nobody adds one in-process later.
- **SDK = the ADR-0009 base protocol + optional capabilities**, all discovered from the connector object (no registry changes; the ADR-0008 scan pattern is untouched):
  - base (mandatory): `name`, `validate_config`, `sync(source, run)`, `health(source, run)`;
  - `oauth_spec()` → the provider's authorize/token endpoints, scopes, and extra params — presence makes the framework drive §1's flow for this connector type;
  - `fetch_changes(source, cursor, run)` — presence enables §3 incremental sync;
  - `map_acl(raw, ctx) -> frozenset[str]` — presence marks documents as connector-ACL'd (§2, `acl_enforced=true`) and **requires** the F-CB-3 negative-test kit to pass for this connector.
- **The execution context is framework-supplied — connectors never fetch their own credentials.** The framework constructs a per-run **`ConnectorRun`** and passes it to `sync` / `fetch_changes` / `health`: it carries an **already-authenticated, egress-guarded HTTP client** (the framework resolves `auth_secret_ref` through the vault and attaches the credential to the client — a raw token is never handed to connector code) plus bounded-run parameters; `map_acl` receives a pure **`AclMappingContext`** — a frozen identity snapshot (case-folded email → user-id map, the tenant principal vocabulary, and the evaluation timestamp) — so ACL mapping stays deterministic and unit-testable. Connector code **never** reads the vault, the DB, or mutable module state; the conformance kit pins these prohibitions (a connector that imports the secrets service or a repository fails conformance). The `web` connector simply ignores the auth capability of its `run` (its signature migrates in the same change, F-CB-1).
- **Vendor boundary:** connectors expose domain types only (ADR-0004). The Drive client is **plain `httpx` against the Drive REST v3 / OAuth endpoints — no Google SDK** (the "prefer an HTTP boundary" rule; unlike MCP there is no moving protocol here justifying an SDK, just versioned REST).
- **Conformance kit (F-CB-5):** a net-new test suite parametrized over `registered_types()` asserting, per connector: protocol surface, domain-types-only returns, typed `ConnectorError`s, and — per declared capability — cursor round-trip/fallback semantics and fail-closed ACL mapping. `web` and `gdrive` both pass it; the kit + a "build a connector" doc are the E1-5 deliverable, and the *next* managed connector is the real proof the SDK holds.

### 5. First managed connector — Google Drive, v1 scope

- **Read-only**, OAuth scope `https://www.googleapis.com/auth/drive.readonly` (content + metadata + per-file permissions). Config selects what to sync: the connected account's **My Drive**, a specific **folder**, or a **Shared Drive** (`config: {mode: my_drive|folder|shared_drive, folder_id?, drive_id?}`).
- **Content:** Google-native types exported to text (Docs → text, Sheets → CSV, Slides → text); binary formats the existing ingestion pipeline already parses (PDF, DOCX, …) downloaded within a size cap (`GDRIVE_FETCH_MAX_BYTES`); everything else skipped and counted in sync health.
- **Egress:** all traffic goes to a **fixed pinned host set** — `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com` — over a guarded httpx client (https-only, timeouts, streamed size caps, descriptive UA), reusing `app/net/egress.py` exactly as MCP does; per-tenant rate limiting reuses the existing limiter, and Drive `429/Retry-After` backs off. There is no user-supplied URL anywhere in this connector; a request leaving the pinned host set is a defect at the ADR-0009 §3 bar.
- **`sources` additions (one migration):** `auth_secret_ref` (uuid, null), `sync_cursor` (text, null), `connected_account` (jsonb: email, null); the same migration widens `ck_secrets_kind` for `connector_oauth`; new `SourceStatus.PENDING_AUTH`; contract `SourceType` enum gains `gdrive` and `SourceStatus` gains `pending_auth`.
- **Health:** the existing probe surface reports token validity (a bounded `about.get`), cursor state, last ACL refresh, and the unmapped-ACL count — the connect/consent UI (F-CB-4) renders these plus **reauthorize required**.
- **Deployment prerequisite (documented in F-CB-5's docs):** a Google Cloud OAuth app registration; `drive.readonly` is a Google-**restricted** scope, so a public/production verification review applies to a real deployment — local/dev runs use test-mode credentials. This is operational cost, not architecture.

### 6. Boundary table — no new row needed

The ADR-0004 §6 row **"External source connectors → `backend/app/connectors/<name>/`"** already covers `connectors/gdrive/` — it is the single module that talks to Google (Drive *and* Google's OAuth endpoints). The generic OAuth machinery (`connectors/oauth.py`, provider-agnostic) and the callback route are framework code with no vendor specifics. No `AGENTS.md` edit is required by this ADR.

## Consequences

- **The moat gets real.** Permission-aware retrieval over live enterprise content — the E1-1/E1-2 promise — lands with the ACL model spec 0004 §2.2 already decided, enforced at the two existing chokepoints rather than a new one.
- **OAuth is built once.** The flow, state discipline, vault storage, and refresh handling are framework-level; the second managed connector (Slack/Confluence) implements `oauth_spec()` + `map_acl()` + `fetch_changes()` and inherits the rest — that drop-in is the SDK's success criterion.
- **Deliberate under-sharing.** Email-based identity mapping, denied domain-shares, and unexpanded groups mean some legitimately-accessible documents stay invisible (counted, surfaced in health). That is the safe failure direction; group expansion + a verified workspace↔tenant domain link (Directory/SCIM territory) are the recorded follow-ups that widen it.
- **New operational surface:** a Google OAuth app registration per deployment (restricted-scope verification for production), ACL-freshness tuning (the window is the revocation-enforcement bound), and an OpenSearch mapping bump + reindex.
- **Delivery (ADR-0008):** this ADR is the serialized seam. Then: **F-CB-0** (contract freeze: connect/callback wire + `gdrive` config/status shapes) → parallel **F-CB-1** (OAuth + vault, backend) → **F-CB-2** (Drive connector + ACL mirror + incremental sync) → **F-CB-3** (negative-test kit) ‖ **F-CB-4** (connect/consent + health UI, after F-CB-0) → **F-CB-5** (SDK docs + conformance kit). Each its own issue/PR with `Closes #`.

## Resolved decisions (sponsor 2026-07-18; remainder sponsor-delegated to this ADR)

1. **First connector: Google Drive** (sponsor, recorded on [#289](https://github.com/k-sandhu/lumen-copilot/issues/289)).
2. **AuthN:** OAuth 2.0 authorization-code + PKCE, tenant-admin-initiated (**every managed-source mutation — create/connect/reconnect/sync-now/disconnect — is admin-gated at action time against current roles**; retrieval stays T0, the mutations are T1); refresh token in CC-C (`SecretKind.CONNECTOR_OAUTH` + widened `ck_secrets_kind`, `sources.auth_secret_ref`); access tokens in memory only; **opaque single-use server-side `state` handle** (the PKCE verifier and all flow bindings stay in Redis, never in the browser) with atomic consumption, **monotonic per-source connect-generation invalidation**, and full re-authorization at callback time; platform-level OAuth client config (BYO-client deferred).
3. **ACL mirror:** **exclusive enforcement modes** (`acl_enforced` — connector documents get *only* the fresh mirrored intersection; owner/grants legs do not apply; the mode is a **mandatory no-default argument at every write**, derived structurally from the connector) · email-based user mapping on the **admin-attested directory** (sync-time snapshot; hard gate: self-service email change / SSO must switch mapping to verified identities first) · `anyone` → tenant-wide (the subset proof holds) · **domain-shares denied in v1** (no verified domain binding) · groups unexpanded ⇒ deny · empty/unknown/stale (window, default 24 h) ⇒ deny · the Drive effective-read algorithm (deleted / **any expiration present** / metadata-view / unknown ⇒ deny; inheritance reduced per `inheritedPermissionsDisabled`) · stored as `acl_enforced`+`acl_principals`+`acl_synced_at` in Postgres + the OpenSearch mapping · enforced by widening `_document_permitted` and `SearchAllowFilter` in lockstep · spec 0004 §2.2 updated to the exclusive split in this change.
4. **Change detection:** polling via the **page-shaped `SyncPage` iterator** (per-page atomic mutation+cursor commits; terminal page = new baseline; Drive Changes API with drive-scoped tokens for Shared Drives), start-token-before-enumeration, **container-cascade propagation** (a folder/drive permission change invalidates descendants' ACL freshness unless refreshed in-run), identity-based reconcile via `external_id`, ACL freshness advanced only on examined-or-attested documents, periodic beat + on-demand; webhooks out (E7-2).
5. **SDK:** in-process first-party capability protocols on the ADR-0009 base (`oauth_spec` / `fetch_changes` / `map_acl`), executed against a **framework-supplied per-run context** (authenticated egress-guarded client + frozen `AclMappingContext`; connectors never touch the vault/DB); no sandbox until third-party connectors are considered; plain-HTTP vendor boundary (no Google SDK); conformance kit parametrized over registered connectors.
6. **Governance:** every managed-source mutation admin-gated at action time (INV-5); additive `source.connected` audit action **recorded in spec 0004 §2.4 in this same change**; denied **initiations** audited as `permission.denied` from the JWT-bound actor, callback-stage failures as `source.connected` `outcome=denied|error` when a trusted tenant resolves (ops-telemetry otherwise); read-only scope — write-back stays E5/T2+, untouched.
