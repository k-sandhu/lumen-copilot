# Spec 0004 — Security & Domain Invariants (closes OD-4)

> Closes **OD-4** in [0001-open-decisions.md](0001-open-decisions.md). Decided with the human sponsor in session on **2026-06-18**. Derives the concrete security/domain invariants from the decided scope ([spec 0003](0003-product-scope-and-mission.md)) and the landed stack/boundaries ([ADR-0003](../architecture/0003-application-stack.md), [ADR-0004](../architecture/0004-architecture-boundaries-and-adapters.md)), and turns each invariant into a **negative-test category** (fills [AGENTS.md](../../AGENTS.md) §9).

**Status:** adopted. **Last reviewed:** 2026-06-18. **Tracking issue:** [#14](https://github.com/k-sandhu/lumen-copilot/issues/14).

## 1. Purpose & precedence

The four mission filters ([spec 0003](0003-product-scope-and-mission.md) §2 — *permissioned / cited / read-before-write / auditable*) are intent. This spec turns them into **enforceable invariants**: each names a single chokepoint module (per [ADR-0004](../architecture/0004-architecture-boundaries-and-adapters.md) §"Cross-cutting chokepoints") and a **negative test** that fails when the invariant is violated. Per `AGENTS.md` §4, these invariants sit **above** specs/ADRs/code: when anything conflicts with an invariant here, the invariant wins.

**One rule governs the whole spec: deny by default.** Absence of an explicit grant is denial — for tenants, for documents, and for actions.

This spec is the source of truth for `AGENTS.md` §9's negative-test set. It **closes OD-4 in full**; sub-decisions whose *implementation* is deferred past the MVP (SSO IdP wiring, connector-ACL mirroring, audit hash-chain) are **decided here** with a `revisit-at-implementation` note so nothing is left to silent defaulting.

## 2. Decisions

### 2.1 Tenancy isolation (CC-2, [#17])

- **Model: single PostgreSQL database, row-level tenancy.** Every tenant-scoped table carries a non-null `tenant_id` (FK → `tenants.id`). No schema-per-tenant, no DB-per-tenant (premature for the MVP; row-level matches the shared-infra deployment in [spec 0003](0003-product-scope-and-mission.md) §3).
- **Primary enforcement — repository predicate.** All relational access goes through `db/` repositories that require a tenant scope; a query against a tenant-scoped table with no `tenant_id` predicate is a boundary violation (review now; smoke-grep once wired). Repositories take the resolved tenant from `auth/`, never from request-body input.
- **Defense in depth — Postgres RLS.** Enable row-level security on tenant-scoped tables with a policy keyed off a per-request session GUC (`SET LOCAL app.tenant_id`). RLS is the backstop if a predicate is ever forgotten. *(Implemented [#17]: migration `0007_tenancy_rls` ENABLEs + FORCEs RLS on every tenant-scoped table with a policy `USING/WITH CHECK (current_setting('app.tenant_id', true) = 'bypass' OR tenant_id = current_setting('app.tenant_id', true)::uuid)`. A missing GUC → NULL → no rows (fail-closed); the `bypass` sentinel is the deliberate exemption for the pre-identity/system lookups — login resolving a tenant from an email, the seed. The GUC is bound per-transaction by `app.db.tenant_context` on the request path (`current_tenant`), the Celery task path (`tenant_session_scope`), and the chat answer runtime. **Deployment requirement:** the application must connect as a **non-superuser, non-`BYPASSRLS`** role — a superuser/`BYPASSRLS` role ignores RLS, so the backstop is inert for it (`FORCE` binds the table owner but not a superuser). The local compose `lumen` role is currently a superuser; hardening it to a least-privilege app role is tracked separately.)*
- **Vectors are tenant-scoped too:** pgvector rows carry `tenant_id`; every retrieval query filters on it (§2.2).
- **No cross-tenant learning or leakage** (non-goal, [spec 0003](0003-product-scope-and-mission.md) §6): tenant content never trains shared models nor crosses the boundary.
- **Existence non-disclosure:** a cross-tenant resource access returns **404**, never 403 — tenant A must not learn that tenant B's resource exists.

### 2.2 Permission / ACL model (CC-1, [#18])

- **"Permitted to see"** = `same tenant` **AND** `requester ∈ resource.effective_allow_set`, where the allow-set is computed from **ownership + explicit grants + mirrored source ACL**. The same predicate gates **retrieval candidates and citations** — a citation can never point to a passage the user could not have retrieved.
- **Uploaded documents (MVP):** each document has an `owner_id` within its `tenant_id`. **Default: a user sees only their own documents.** Sharing is explicit, via a `grants` table (`principal → resource → role`); principals are `user | group | role`, resources are `collection | document`. A grant on a collection cascades to its documents. *(Implemented [#18]: migration `0008_grants` adds the tenant/owner-scoped `grants` table — `(tenant_id, resource_type ∈ {collection,document}, resource_id, principal_type [modelled `user|group|role`, MVP emits `user`], principal_id, role, granted_by, created_at)`, UNIQUE on `(tenant_id, resource_type, resource_id, principal_type, principal_id)`, indexes on `(tenant_id, principal_id)` and `(tenant_id, resource_type, resource_id)`, and the same fail-closed RLS policy as `0007`. The single `retrieval/` permission filter (`app.retrieval.queries` — the INV-2 chokepoint) widens from `owner_id IN owners` to `owner OR EXISTS(grant to the requester's `user` principal on this document OR its collection)`, so a collection grant **cascades** to its documents and every retrieval path (semantic, lexical, `search_documents`, `list_documents` [#371], `get_document`) honors grants identically. `services/grants_service.py` is the testable seam — `create_grant`/`revoke_grant`, owner-or-tenant-admin only, cross-tenant/non-owned → 404, audited (`permission.granted`/`permission.revoked`, additive to §2.4). **Deferred to a follow-up (deliberately out of [#18]):** the grant **HTTP API + sharing UI** (no contract change here), and `group`/`role` principals + the mirrored connector ACL below — `revisit-at-implementation`.)* *(**`group` principals now implemented** — [ADR-0022](../architecture/0022-group-access-model.md), issues #534/#538: tenant-scoped `groups`/`group_members` (migration `0041`, same fail-closed RLS policy); `grants` needed **no** migration because `principal_type` already admitted `group`. The INV-2 chokepoint widens in both of its homes — the `EXISTS` in `app.retrieval.queries` and the engine mirror via `GrantRepository.granted_resource_ids` — so a grant to a group admits every member on both the SQL and OpenSearch paths. Membership is re-read per request and never cached in a token, so removal revokes on the next request. Tenant-wide visibility is a per-tenant `kind='system'` group with **derived** membership. `role` principals remain unsupported (422) — nothing needs them, and admitting them unreviewed would widen INV-2 for free.)*
- **Connector documents:** at ingestion each external document stores a **mirrored ACL principal-set** (the source's allow-list, normalized to tenant principal IDs), refreshed on sync. Retrieval intersects the requester's principal set with the document's allowed set. **Stale or unknown ACL ⇒ deny** (configurable freshness window). *(Refined at implementation, [ADR-0019](../architecture/0019-connector-sdk-and-oauth.md) §2, 2026-07-18: enforcement modes are **exclusive** — a connector-ACL document (`acl_enforced`) is governed **solely** by the fresh mirrored intersection; the ownership and explicit-grants legs of the allow-set above apply only to non-connector documents. Ownership/grants never widen access to a connector document, so a Lumen grant cannot admit a user the source denies — the "never escalates" rule below made structural.)*
- **Single chokepoint:** the permission filter lives **inside `retrieval/`**, keyed off the identity resolved in `auth/`. There is **no retrieval path that skips the filter** (ADR-0004). Citations inherit the guarantee because they are drawn only from retrieved passages.
- **Never escalates:** the system mirrors and enforces source ACLs; it never grants access a source would deny ([spec 0003](0003-product-scope-and-mission.md) §6).

### 2.3 Identity & authentication (CC-3, [#19])

- **MVP — app-managed identity.** Email + password (**Argon2id** hashing, per-user salt). Auth issues a short-lived **access JWT** (≤ 15 min) + a rotating **refresh token** (httpOnly, revocable). Token claims: `sub` (user_id), `tenant_id`, `roles`. **Tokens are validated only in `auth/`** (ADR-0004); no other module decodes a token or trusts a client-supplied identity/tenant.
- **One principal → one tenant** (MVP). Tenant is bound at the token, never taken from request input.
- **Roles (MVP RBAC):** `member` (KW/NH/MGR/EXEC — chat, own docs), `admin` (ADM — tenant config, user management), `security` (SEC — read the audit trail). Role checks live in `services/`.
- **End-state SSO — decided default: OIDC via Keycloak.** When SSO lands, identity federates through an external OIDC provider; **Keycloak** is the recorded default (mature OSS, realm-per-tenant fits multi-tenancy, OSS-only per ADR-0003). The `auth/` adapter abstracts the token source, so app-managed → OIDC is a localized swap (ADR-0004 adapter rule). *(`revisit-at-implementation` when SSO is scheduled; app-managed remains the supported fallback.)*

### 2.4 Audit taxonomy (CC-8, [#23])

- **One append-only sink** (ADR-0004 "audit through one sink"). Ops telemetry (structlog/OTel/Prometheus) is **separate** from this product audit log ([backend/AGENTS.md](../../backend/AGENTS.md)).
- **Event types (MVP):** `auth.login`, `auth.login_failed`, `auth.logout`, `collection.created`, `document.uploaded`, `document.viewed`, `document.downloaded`, `document.deleted`, `retrieval.query`, `answer.generated`, `permission.denied`, and (reserved for the write tiers) `action.requested|approved|executed`.
- **Additive event types (later-accepted features; the taxonomy only ever grows — deny-by-default preserved, no action relaxed):** connector sources ([ADR-0009](../architecture/0009-connector-framework-and-web-source.md) §5) — `source.added`, `source.synced`, `source.deleted`; explicit ACL grants (§2.2, [#18]) — `permission.granted`, `permission.revoked`; per-tenant admin settings ([#148]) — `tenant.settings_updated`; the **encrypted per-tenant secrets vault** ([#209]) — `secret.created`, `secret.accessed`, `secret.deleted` (`secret.accessed` records **who/what** read a credential — the adapter/actor — **never the value**); managed-connector OAuth ([ADR-0019](../architecture/0019-connector-sdk-and-oauth.md)) — `source.connected` (emitted on callback success **and**, with `outcome=denied|error`, on failed/denied **callback-stage** flows whose `state` record resolves to a trusted tenant; a denied/errored **initiation** — the JWT-authenticated connect/create/reconnect request, where no state exists yet — emits the existing `permission.denied` from the token-bound actor; callbacks whose `state` does not resolve are ops-telemetry only, never a tenant-attributed audit row fabricated from untrusted input; metadata carries the account email + granted scopes, **never tokens, authorization codes, or PKCE verifiers**) and `user.identity_attested` (a tenant admin attests a member's email identity for connector-ACL mapping, incl. the provider-verified auto-attestation of the connecting admin — ADR-0019 §2). group management ([ADR-0022](../architecture/0022-group-access-model.md) §2) — `group.created`, `group.updated`, `group.deleted`, `group.member_added`, `group.member_removed` (a change to *who can see what* must be provable after the fact; the lazily-materialised tenant-wide group is audited too, exactly once); direct media upload/transcription ([spec 0008](0008-direct-media-uploads-and-timestamp-citations.md), [ADR-0023](../architecture/0023-direct-media-ingestion.md)) — `document.upload_started`, `document.upload_aborted`, `document.upload_expired`, `document.transcribed` (completion reuses `document.uploaded`; access-capability issuance and transcript preview reuse `document.viewed`, while an explicit download uses `document.downloaded`). The canonical mirror is `app.domain.audit.AuditAction` (pinned by `tests/test_audit_taxonomy.py`).
- **Required fields (every event):** `event_id` (uuid), `ts` (UTC, ISO-8601), `tenant_id`, `actor_id` (or `system`/`anonymous`), `action`, `resource_type`, `resource_id`, `outcome` (`allowed|denied|error`), `request_id` (correlation), `source_origin`, `metadata` (json). For `retrieval.query`/`answer.generated` add: query hash, retrieved document IDs, model ID, citation count.
- **Where the action came from — `source_origin` + `source_ip`** *(amended 2026-07-30, [#546]; supersedes the earlier "`source_ip` required on every event")*. `source_origin` is **required** and typed: `client` (a request from a peer whose address is known) · `system` (background/scheduled work — no client exists) · `unknown` (a request whose peer address could not be determined, e.g. an AF_UNIX peer behind a socket-mode proxy). `source_ip` is recorded **if and only if** `source_origin = 'client'`, and is NULL otherwise — enforced by a database CHECK constraint, not by the writing service alone. **No address offered at all is `unknown`, never `client`** — a writer that assumes "no sentinel came back, so it must be a real address" produces the one pair the constraint forbids, and since audit writes ride the caller's transaction that aborts the action being recorded. (That is not hypothetical: it is how the `/auth` routes, which call the repository directly and so bypass this envelope's own non-empty check, would have taken down login on any socket-bound deployment.)
  *Why this changed:* the original clause required `source_ip` on every event, which a background task cannot satisfy — it has no client address. Callers passed a sentinel string, the `INET` column rejected it, and because an audit write deliberately shares the transaction of the action it records (so the two commit atomically), **the rejection rolled back the action itself**. The rolling session summariser never persisted once on Postgres as a result. Splitting the fact in two makes the invariant stateable without an exception clause: *every event records its origin, and an event claiming a client records that client's address*. `unknown` is deliberately distinct from `system` — "a person did this and we could not see from where" is a different operational fact, and a different problem to fix, from "the platform did this".
- **Retention:** ≥ **365 days** default (per-tenant configurable later); events are never deleted before retention elapses.
- **Tamper-evidence:** the table is append-only — the application DB role holds **no `UPDATE`/`DELETE`** grant on it. A per-event **hash-chain** (`hash = H(prev_hash ‖ event)`) is the decided integrity mechanism. *(Append-only is required at MVP; the hash-chain may land in a follow-up within M0 — `revisit-at-implementation`.)*

### 2.5 Read-before-write — risk tiers (mission filter #3)

| Tier | Meaning | Examples | Gate |
|---|---|---|---|
| **T0** | Read-only | retrieve, answer, summarize, draft-in-chat | none — **the entire MVP is T0** |
| **T1** | Reversible internal write | create collection, upload/delete *own* document, rename, **write/delete an own artifact** ([#208]) | authorized owner; audited; no extra approval |
| **T2** | Consequential / external write | write-back to a source, send, external share | **explicit human approval** in-session + stated risk tier — **out of MVP** (E5/CC-7) |
| **T3** | Destructive / irreversible external | bulk delete, change source permissions | approval **+** confirmation — out of MVP |

- **Invariant:** no T2/T3 action executes without a recorded approval. The MVP asserts the *negative*: there is **no code path** that performs a T2+ action, and any attempt is rejected. *(Implemented [#207]: the governed **tool platform** (CC-7, the action/tool-call gateway) lands the seam that makes this structural. A tool self-declares its `risk_tier` on a `ToolDefinition` (`app/services/tools/`); the single `ToolRunner` chokepoint routes every invocation through allow-list → approval gate → bounded execute → uniform `ToolResult` → `tool_invocations` row + `tool.invoked`/`tool.result` audit (additive to §2.4). A `requires_approval` (⇒ T2+) tool **blocks on the `ApprovalGate`** before its handler runs; the default `DenyAllApprovalGate` denies fail-closed, so an unapproved consequential action is never executed — the gate is **wired but inert** because the whole MVP ships T0 tools only. `ToolDefinition` refuses at construction to register a write-tier tool that does not `requires_approval`, so INV-7 is a build-time guarantee, not runtime discipline. The three retrieval tools are migrated behind the registry with identical behaviour. **Deferred (deliberately out of [#207]):** the specific T2+ tools (web/file/`run_python`/MCP — their own issues) and the approval **UI** (F-ADMIN-TOOLS) — `revisit-at-implementation`.)*
- **Artifact store ([#208], CC-12).** Files an agent/run *produces* (distinct from user-uploaded `documents`) persist through the tenant/owner-scoped `artifacts` table + the `storage/` adapter (`artifacts/` key prefix, allowlist/size cap, `artifacts.*` audit actions, RLS backstop like every scoped table §2.1). Writing an artifact is a **T1** action — owner-gated, audited, no extra approval; a cross-tenant/non-owned artifact is **404** (INV-1/INV-2). The file-writing *tool* and code-sandbox *capture* that call this seam, and the artifact *panel UI*, are follow-ups. *(Owner-**or-grant** visibility is the modelled end-state; the `grants` table's `resource_type` CHECK admits only `collection`/`document` today, so widening artifact visibility to explicit grants is a deliberate `revisit-at-implementation` follow-up — the service's single visibility chokepoint is where it lands.)*
- **Reusable code sandbox ([#457], [ADR-0020](../architecture/0020-reusable-root-sandbox-sessions.md)).** A mutable sandbox is scoped to exactly one `(tenant, owner, chat session)` and reused only within that boundary. UID 0 inside it grants package/filesystem authority but never host authority: host mounts, the container-engine socket, application secrets, and model-authored network egress remain absent. Package acquisition is a separate policy-checked runner operation performed before tenant inputs are staged. Session create/reset/close and cancellation emit `sandbox_session.created`, `sandbox_session.reset`, `sandbox_session.closed`, and `code_run.cancelled`; a missing lifecycle/run audit event fails INV-6. Cross-tenant, non-owner, and other-chat reads or mutations return 404 under INV-1/INV-2.

[#208]: https://github.com/k-sandhu/lumen-copilot/issues/208

## 3. Invariants → negative-test categories

This table is the canonical set that `AGENTS.md` §9 references. Every feature touching a chokepoint ships the matching negative test (test-first, `AGENTS.md` §9).

| ID | Invariant | Chokepoint | Negative test (must fail closed) |
|---|---|---|---|
| **INV-1 Tenancy** | A request in tenant A never reads/writes tenant B data. | `db/` predicate (+ RLS backstop) | cross-tenant read/write → **404** (not 403); no rows returned |
| **INV-2 Permission** | A user receives only passages/documents in their effective allow-set. | `retrieval/` filter (keyed off `auth/`) | unauthorized retrieval → passage **excluded**; direct fetch → **404** |
| **INV-3 Citation integrity** | No asserted fact without a resolvable citation to a **permitted** passage. | chat runtime (`services/` + `retrieval/`) | answer with unsourced/forbidden citation → **blocked/flagged**; prefer "couldn't find it" |
| **INV-4 Authn** | No access without a valid, unexpired token bound to a tenant. | `auth/` | missing/expired/invalid token → **401** |
| **INV-5 Authz (role)** | Actions require the role that authorizes them. | `services/` | wrong-role (e.g. member → admin route, non-security → audit) → **403** |
| **INV-6 Audit** | Every retrieval/answer/auth/denied-access emits an audit event. | one audit sink | action with no emitted audit event → **fail** |
| **INV-7 Read-before-write** | No consequential (T2+) action without recorded approval. | approval-gated action path | unapproved T2+ action → **forbidden** |
| **INV-8 Input/state** | Malformed input and illegal state transitions are rejected at the boundary. | `api/` + `domain/` | malformed body → **422**; illegal transition → **409/422** |

These extend the existing `AGENTS.md` §9 baseline (unauthorized → denied, wrong-role → forbidden, illegal transition, malformed input, broken invariant) with the concrete tenancy/permission/citation/audit categories above.

## 4. Data-model implications (guidance for the DB-models issue)

Non-binding shapes that satisfy the invariants; the migration issue refines them:

- **Every tenant-scoped row carries `tenant_id` (non-null, FK, indexed).** Permission-sensitive rows also carry `owner_id`.
- `tenants`, `users(tenant_id, email, password_hash, roles)`, `collections(tenant_id, owner_id)`, `documents(tenant_id, owner_id, collection_id, source, mime, …)`, `grants(tenant_id, resource_type, resource_id, principal_type, principal_id, role)`, `chunks(tenant_id, document_id, ord, text, embedding vector, char_start, char_end)`, `chat_sessions(tenant_id, owner_id, model)`, `messages(tenant_id, session_id, role, content)`, `citations(tenant_id, message_id, chunk_id, char_start, char_end)`, `audit_events(…fields from §2.4…)`.
- **Vector + ACL/metadata live in the same row** ([backend/AGENTS.md](../../backend/AGENTS.md)) so permission-aware retrieval is one `WHERE` clause: `WHERE tenant_id = :t AND <allow-set predicate>`.

## 5. What this closes / leaves open

- **Closes OD-4 in full:** tenancy model, permission/ACL model, identity & authn (incl. the SSO IdP-technology default ADR-0003 deferred to CC-3), audit taxonomy, and read-before-write tiers — each with an invariant and a negative-test category.
- **No part of OD-4 remains "ask, don't default."** Items marked `revisit-at-implementation` (the RLS backstop — **now implemented, [#17]**; the explicit-grants permission filter — **now implemented, [#18]** (the grant HTTP API/UI remains a follow-up; **`group` principals now implemented** — [ADR-0022](../architecture/0022-group-access-model.md), #534/#538; `role` principals deliberately still unsupported); connector-ACL mirroring, SSO/OIDC wiring, audit hash-chain — still sequenced later) are **decided**; each remaining one reconfirms against this spec when claimed.
- **Feeds:** `AGENTS.md` §9 (negative-test set — updated in the same change); strikes **OD-4** in [0001-open-decisions.md](0001-open-decisions.md).
