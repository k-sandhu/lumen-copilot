## Prior findings

1. **PARTIALLY RESOLVED — loop budget.** `fit_transcript()` is called before every ordinary `stream_tools` turn and again before forced synthesis; for the runtime's plain persisted history it recomputes the last user-question boundary correctly, sheds only pre-question history, preserves the live tool-call/result tail, and raises `context_too_large` when the *counted content* of the protected tail does not fit. However, `estimate_message_tokens()` does not count assistant `tool_calls`, arguments, ids, result names, or `tool_call_id` wire fields, so an actually oversized live tail can still be sent. The new runtime regression would fail without the ordinary-loop refit, but it records content bytes only and exits on the pre-synthesis refusal, so it covers neither this wire-metadata bypass nor the forced-synthesis call.
2. **PARTIALLY RESOLVED — retrieval caps.** Explicit `k=20` is hard-clamped in both `search_text` and `search_documents`, and `_render_passages()` enforces `snippet_budget` with the tool's own 600-character ceiling. Two paths remain: omitted/invalid `search_documents.k` returns the unclamped default 10, and `list_documents` ignores `ctx.max_k` entirely (a tight `max_k=3` still permits 50).
3. **RESOLVED — tool wire counting.** `_tools_wire_text()` currently mirrors `LLMGateway._to_wire_tools()` key-for-key and structure-for-structure, with deterministic JSON rendering, and the same helper is used by both `assemble_context()` and `estimate_message_tokens()`.
4. **RESOLVED — heuristic.** The tokenizer-failure fallback now uses UTF-8 byte length, a conservative upper bound for the supported subword tokenizers. The remaining under-count is message wire metadata, not this fallback.
5. **RESOLVED — lazy imports.** Both `litellm` imports are inside their protective `try` blocks, so import/initialization failures degrade to the byte heuristic or fallback model window.
6. **PARTIALLY RESOLVED — config.** The field validators are correct (`fallback > 0`, `headroom >= 0`), but the cross-field validator omits the fixed 1,024-token safety margin. For example, fallback `1025` plus headroom `1024` is accepted, then yields the assembler's 1-token floor and immediately refuses even an empty prompt. Validate the derived budget (`fallback - headroom - safety_margin > 0`) or centralize that calculation in a validated config type.

## New findings

1. **major — `backend/app/llm/context.py:322` / `backend/app/llm/gateway.py:199` — grown-message wire data is still unbudgeted.** The estimator sums only `m.content + 4`, while the gateway additionally sends `tool_calls[*].function.arguments`, call ids/names, `tool_call_id`, and message names. A focused probe with a 200-token budget produced `estimated=18`, actual serialized message wire length `5231`, and `fit_transcript()` returned the payload unchanged. A model can therefore emit a large tool argument and make the next ordinary or forced-synthesis provider call exceed the window despite the new guard. **Fix:** put provider-neutral message-wire rendering beside the existing tool renderer in `llm/`, have the gateway and estimator share it, and add runtime regressions for oversized tool arguments and forced synthesis that measure the full wire payload.
2. **major — `backend/app/services/chat_service.py:462` — the issue's count-based history window was not replaced.** `send_message()` still passes only `prior[-_HISTORY_TURNS:]` (`_HISTORY_TURNS = 20`), despite #410 guidance explicitly requiring history to become token-budgeted. More than 20 tiny messages are silently discarded before the assembler sees them, so the assembler cannot retain them even when they fit and cannot log the actual dropped set for AC-1. **Fix:** remove the upstream 20-message slice/pass the available chronological history into the assembler, and add an end-to-end test with >20 short messages that all fit.
3. **minor (performance) — `backend/app/llm/context.py:367` — refitting repeatedly tokenizes the full transcript and the shedding loop is quadratic in retained history.** This is tolerable only while the invalid 20-message cap remains; after that cap is removed, every deletion re-runs `estimate_message_tokens()` across the remaining list, and every model turn re-tokenizes unchanged tools/system/history. **Fix:** compute tool and per-message costs once, carry the running total, and shed via cached prefix costs rather than full recounts.
4. **minor (comment/artifact discipline) — `backend/app/llm/context.py:138`, `backend/tests/test_llm_context.py:282`, `codex-review-424.md:1`.** The counter docstring still promises the old “~4 chars/token” fallback; the test comment says it forces an import failure but does not monkeypatch import failure; and the prior review markdown is committed as a product-PR artifact. **Fix:** update the stale prose, add a real import-failure regression, and remove the review artifact from the PR.

No vendor type leaks or new nondeterministic ordering were found. The `llm/` boundary remains intact and tool ordering/JSON key order are deterministic.
